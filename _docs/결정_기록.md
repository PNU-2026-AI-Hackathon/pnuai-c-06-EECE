## D-1. 펌웨어 파서 — 정적 분석으로 가고, UNRESOLVED 채널을 처음부터 만든다

**2026.08.18 · 미결 상태로 D-10 을 맞을 수 없어서 결정함**

### 선택지

순수 정적 분석 · AI 추출 · 둘의 혼합.

### 실제 난이도 분포

| 난이도 | 예 | 정적 | AI |
|---|---|---|---|
| 쉬움 (대부분) | `#define LED_PIN 13` · `const int TRIG = D2` | ✅ | ✅ (이득 없음) |
| 중간 | `const int pins[] = {2,3,10}` | 파서 필요 | ✅ |
| 어려움 | `display.begin(SDA, SCL)` 라이브러리 래퍼 | ✕ | ✅ |
| **불가능** | `#ifdef BOARD_REV_B` | ✕ | **✕** |

**조건부 컴파일은 AI 로도 안 풀린다.** 어느 브랜치가 빌드되는지는 `platformio.ini`
빌드 플래그에 있지 소스에 없다. 빌드 시스템 문제라 두 방식이 똑같이 실패한다.

### 결정적 근거 — 틀렸을 때 무엇이 일어나는가

| | 정적 분석 실패 | AI 실패 |
|---|---|---|
| 증상 | 핀을 **놓친다** → R08 오탐 | **없는 핀·없는 줄 번호를 지어낸다** |
| 재현성 | 100% 결정적 | 같은 파일에 다른 답 |
| 근거 | 정확한 `file:line` | 줄 번호를 지어낼 수 있음 |

우리 제품 정체성이 **"근거가 파일 몇 줄인지까지 나온다"** 다. 사용자가 그 줄을 열어본다.
2026.08.18 하루에 고친 화면 버그 3개가 전부 **없는 사실을 말하는 것**이었다.
AI 추출은 그 실패를 파서 층으로 옮긴다.

### 그래서 진짜 결정은 "AI 냐 아니냐"가 아니다

**나중에 바꾸면 두 번 만들게 되는 것은 AI 가 아니라 UNRESOLVED 채널이다.**

```
파서가 D10 을 읽음         → 사실. file:line 을 붙여 반환
파서가 pins[i] 를 못 읽음  → "못 읽었다 (main.ino:44, 배열 인덱스)" 를 위치와 함께 반환
```

파서가 **항상 성공한다고 가정하고 짜면** 나중에 통째로 갈아엎는다.
**못 읽은 자리를 위치와 함께 보고하게 짜면** AI 는 그 자리에만 붙이면 된다 — 재작성이 아니라 추가.

이건 `CLAUDE.md` 2-2("모르면 모른다고 한다")를 파서 층에 적용한 것뿐이다.

### AI 를 붙일 때의 조건

AI 가 제안하고 **결정적 코드가 검증한다.**
AI 가 `{pin: "D10", line: 93}` 을 주면 93번 줄을 열어 그 문자열이 실제로 있는지 확인하고,
없으면 버린다. 검증을 통과한 것만 사실이 된다.

### 8/28 범위

**정적 분석 + UNRESOLVED.** 우리 픽스처(106줄)는 전부 쉬움 구간이라 **R07·R08 이 바로 돈다.**
AI 추출은 남은 기간에 검증이 안 되고, AI 활용 서사는 트랙 B(데이터시트)가 이미 책임진다.

## D-2. GitHub Action — 서사는 본체, 8/28 범위는 얇은 데모

**2026.08.18 · `후보A` 는 "제품의 본체", README 로드맵은 "여유되면" 이라 충돌하고 있었음**

### 둘 다 부분적으로 맞았다

- **본체가 맞는 이유** — 드리프트는 시간에 걸친 문제다. 그러면 CI 가 자연스러운 형태이고,
  일회성 검사는 반복 매출이 없다.
- **여유가 맞는 이유** — Action 의 가치가 **R10 에 종속**되는데 R10 은 트랙 C 맨 끝이다.
  R10 없이 CI 로 돌리면 "매 PR 마다 같은 규칙 2개를 다시 돌린다"라 한 번 돌리는 것과 같다.

### 제3의 길 — R10 을 기다리지 않는다

Action 은 새 기능이 아니라 **포장**이다. 엔진은 이미 CLI 로 돈다.
진짜 비용은 Action 이 아니라 "PR 에서 무엇을 비교하나" 다.

**검사 결과를 커밋 간 diff 하면 된다.**

```
PR 에서 .d356 이 바뀜
   ↓
이전 커밋 검사 결과  vs  이번 커밋 검사 결과
   ↓
"이 변경으로 발견이 3건 → 5건. 새로 생긴 것: R12 PRESENCE_3V3"
```

**이게 R10 없이 드리프트 서사를 만든다.** 회로도가 바뀌자 새 문제가 생겼다는 것을 그대로 보여준다.
그리고 이미 가진 것(CLI · 픽스처 · CI)만으로 된다 — **새 인프라 0.** 배포도 필요 없다,
Action 안에서 엔진이 직접 돌기 때문이다.

### 8/28 범위

**우리 리포에서 도는 얇은 Action.** 반나절 작업이라 "여유되면"이 아니라 **8/27 확정 항목**이다.

> 시간이 모자라면 **자를 것은 Action 이지 트랙 B 가 아니다.**
> Action 은 서사를 강화하고, 트랙 B 는 서사 그 자체다.
