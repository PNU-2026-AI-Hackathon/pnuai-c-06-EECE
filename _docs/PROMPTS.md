## 2. D-10~9 (8/19~20) — 펌웨어 파서 ★ 프로젝트의 생존 조건

> 차별 등급 규칙 5개가 전부 여기에 걸려 있다.

```
펌웨어 소스에서 "코드가 실제로 사용하는 핀"을 추출하는 파서를 만들어줘.

입력: Arduino(.ino/.cpp/.h) 또는 ESP-IDF C 소스 디렉터리
출력: [{pin, mode, file, line, snippet, confidence}]

잡아야 하는 패턴:
- pinMode(N, MODE) / digitalRead / digitalWrite / analogRead
- gpio_config_t 구조체 초기화, gpio_set_direction
- #define / const int / constexpr 로 정의된 핀 상수 (여러 파일에 흩어짐)
- 라이브러리 생성자 인자로 넘어가는 핀 (Wire.begin(sda, scl), SPI 등)

중요:
- 상수 추적이 핵심이다. `#define LED_PIN 34` 가 config.h에 있고
  `pinMode(LED_PIN, OUTPUT)` 이 main.cpp에 있으면 34로 해석해야 한다
- 매크로 연산이나 런타임 계산으로 핀이 정해지면 confidence를 낮추고
  절대 추측하지 말 것. UNRESOLVED로 남긴다
- 정규식만으로는 부족하다. 필요하면 tree-sitter나 pycparser 검토

먼저 접근 방식 두세 개를 비교해서 알려주고, 내가 고른 뒤에 구현해줘.
```

## 7. 비전공 팀원 전용 프롬프트

> 그대로 복사해서 쓰세요. 코딩 지식이 없어도 됩니다.
> 목표는 **규칙 12개 중 8개 이상을 두 분이 커밋하는 것**입니다.

### 규칙 추가

```
규칙 하나 추가하고 싶어.

[여기에 위험한 상황을 아는 대로 설명. 예:]
ESP32의 34번부터 39번 핀은 입력만 되는 핀이야.
그런데 코드에서 여기에 OUTPUT을 걸면 컴파일도 되고 업로드도 되는데
LED가 절대 안 켜져. 원인 찾는 데 반나절 걸림.

모르는 건 나한테 물어봐. 코드는 네가 쓰고, 맞는지는 내가 판단할게.
```

### 오탐 신고

```
이 경고 잘못 뜬 것 같아: [규칙 ID와 네트 이름]

이유: [왜 실제로는 괜찮은지 아는 대로]

왜 떴는지 근거부터 보여주고, 규칙이 틀린 건지 부품 정보가 틀린 건지 구분해줘.
고친 뒤에는 이 경우가 다시 안 뜨도록 테스트로 고정해줘.
```

### 내 커밋 확인

```
지금까지 내가 커밋한 규칙이 몇 개인지, 전체 규칙 중 몇 개인지 알려줘.
git log를 저자별로 정리해서 보여줘.
```
