# to강현...
강현의 상황 : 
오답set : 존재
정답set : 존재

문제
오답 -> 정답 set 부재.


## 해결과정의 문제
오답 -> 정답을 만드는걸 "한번에 범용적인 rule로 표현"을 하는건 추천하지 않는다.
정답-오답 set을 "먼저"만들고. 
이 과정에서는 전기전자 공학부 학우들의 도움을 받아서, 내부 과정은 몰라도 어쨌든 
"오답"->"정답"인 케이스를 만들어야한다.

그리고 "역검산"작업으로 와야한다.

현업에서 대부분의 이러한 정답을 찾아가는 과정은 제일먼저 "데이터 분석"이다.
정답-오답 셋이 없으면 내가한 rule이 맞는지를 모른다. 그럼으로 무한 반복
가장무서운건 다해놨는데? 그게 실제 적용했을때 나 예상과 다를수있따. 

# 해야할일
1. 전기전자공학부 학우 한명을 차출한다. 그래서 "오답"->"정답"셋을 만들게한다.
    - 오답원본은 반드시 별도로 너가 분리하라. (남은 항상 100중 25정도만 믿어라)
    - 오답->정답 과정을 굳이 인수인계로 이해할려고 하지말고, 그냥 나는 몰라도 어쨌든 "작동"
    - 중간 산출물이나 아이디어 과정 (마크다운파일)이런거 만약 있으면 달라해라.
2. 오답-답지 적용때 아주 주의해야함
    - 정답-오답
        1. 정답의 기준이란? (정답의 기준을 세우는것과 풀이 과정을 세우는건 별도)
        2. 오답-> 정답을 오는 과정? 
        3. (정답기준 + 오답set)을 AI한테 먹였을때 얼마나 재현되는지 뽑기 - baseline **정답set을 AI가 모를때 얼마나 맞추는지가 관건**
            - 만약 베이스라인이 성공했을때 (긍정적상황) 이때 AI한테 과정 역검산으로 찾는건 쉬움.. ㄱㅇㄷ
3. baseline vs 내작업 vs 정답 비교를 통해서 점차 점차 점차... 완성해나가는
