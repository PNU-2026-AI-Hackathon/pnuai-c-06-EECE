### 2순위 — A+1 · A+2 전원 레일을 토폴로지로

`graph.py` `signal_nets()` 가 네트 **이름**에 전압 토큰이 있는지로 전원을 판별한다.

```
+VSW · +BATT · VDD_CORE · AVDD      전원인데 전압 토큰 없음  → 못 걸러냄
SPI_3V3_CS · UART_5V_TX             신호인데 전압 토큰 있음  → 잘못 걸러냄
```

우리 보드가 `5V_BUS` · `3V3` 라서 **우연히 맞았다.**
디커플링 캡이 여러 개 붙었는지, 붙은 핀이 대부분 `VCC`/`VDD` 인지로 봐야 한다.
**이게 안 되면 검증 측정이 전부 0건이라 숫자가 거짓말을 한다.**

### 3순위 — 검증 측정

정답은 LLM 이 아니라 **그 프로젝트 개발자가 고친 커밋**이다.

```
1. LLM   커밋에서 "핀/배선을 고친 것 같은 것" 후보를 낸다
2. 코드   그 커밋 diff 를 열어 실제로 그 핀이 바뀌었는지 확인한다 → 아니면 버린다
3. 엔진   커밋 직전 상태를 검사해서 그 결함을 잡는지 본다
```

**LLM 을 판정자로 쓰지 않는다.** 그러면 재는 게 정확도가 아니라 LLM 과의 일치율이 되고,
발표에서 "그 LLM 이 맞다는 건 어떻게 아세요"에 답이 없다.
이건 `결정_기록.md` D-1 의 "AI 가 제안하고 결정적 코드가 검증한다" 를 검증에 적용한 것이다.
