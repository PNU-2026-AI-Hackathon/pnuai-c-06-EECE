## 2. 내가 올린 수정 — 요청서 A++1 과 무엇이 같고 다른가

브랜치: **`fix/unconnected-by-topology`** (`origin/JWJ` 위에 올림)

| | 요청서 A++1 | 실제로 만든 것 |
|---|---|---|
| 판정 기준 | "패드가 하나뿐인 네트는 미연결" | 같음 |
| 놓는 자리 | 미정 | `Netlist.is_dangling()` — 이름 판정 `is_unconnected()` 는 그대로 두고 **추가** |
| 부작용 | 안 적었다 | **테스트 2개가 깨졌고, 그게 발견이었다** (아래) |

### 요청서에 없던 것 — 합성 보드가 틀린 배선을 모델링하고 있었다

`_synth_board()` 가 "배선됨"을 **U1 쪽 패드 하나만** 놓아서 만들고 있었다.
배선은 양 끝이 있어야 배선이다. 한쪽 끝만 있는 네트는 실제로 미연결이고, 고친 엔진도 그렇게 본다.

그래서 이름 있는 네트마다 상대편 패드를 하나씩 놓도록 함께 고쳤다.
**이 수정이 없으면 A++1 은 "기존 테스트를 깨는 변경"으로 보여 되돌려진다.**

### 검증

```
전체 테스트          138개 통과
실제 보드 골든        6건 그대로 (회귀 없음)
KiCad c3v4           미연결 인식 0 → 16
유사 네트 없는 보드    0 → 0        (오탐 안 늘어남)
새 회귀 테스트        고치기 전 실패(미탐 재현) → 고친 뒤 통과
```

R07 은 미탐, **R08 은 오탐**이었다. R08 이 `is_unconnected` 로 걸러내기 때문에
미연결 패드를 "배선됐는데 코드가 안 쓴다"고 신고한다. 요청서에는 R07 만 적었는데
실제로는 두 규칙 다였다.

## 3. 계약이 바뀌었다 — 프론트가 아직 안 쓰는 것

`docs/API_CONTRACT.md` 에 **선택 필드 3개**가 늘었다. 전부 선택이라 **화면은 안 깨진다.**

| 필드 | 어디 | 값 |
|---|---|---|
| `silk` | `connections[]` · `parts[].pads[]` | 보드 실크 라벨 (`D5`) |
| `gpio` | 같음 | GPIO 번호 (`23`) |
| `pads` | `parts[]` | 이름이 뭉치기 전의 패드 목록 |
| `files` | `inputs.firmware` | 펌웨어 파일 수 |

**`apps/web/src/types/api.ts` 에는 넷 다 없다.** 지금은 손해만 있다 —
넷리스트 부록이 `U1.SDIO` 로 보인다. `U1.D5` 로 보일 수 있는데.

> 계약에 한 줄 더 생겼다 — **`pipeline[].detail` 문구는 계약이 아니다.**
> 화면에 그대로 찍기만 하고 파싱하지 않는다. 지금 프론트는 파싱하지 않으므로 맞다.

### 프론트가 할 일 (별건, 작음)

1. `types/api.ts` 에 선택 필드 4개 추가
2. 넷리스트 부록에서 `silk` 가 있으면 실크 라벨로 표시 (없으면 지금처럼 `pin`)
