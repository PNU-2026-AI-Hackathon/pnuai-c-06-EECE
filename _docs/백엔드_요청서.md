## 3. 주의할 것 — **모르고 건드리면 되돌려야 합니다**

### 3-1. LLM 출력은 코드가 원문과 대조합니다

`datasheet/extract.py` 는 모델이 댄 인용문이 **그 쪽 원문에 진짜 있는지** 확인하고,
없으면 그 항목을 버립니다. 실제로 두 번 걸렸습니다 — 지어낸 인용 1건, 그리고
**사람이 손으로 넣은 값을 LLM 이 반박한 것 1건**.

- 인용문 비교는 **공백을 전부 지우고** 합니다. PDF 글자 레이어가 공백을 잃어버립니다
  (화면 `A GPIO, IO level 3.3V` → 추출 `AGPIO,IO level 3.3V`).
  이걸 "공백 하나로 줄이기"로 되돌리면 **진짜 인용문이 지어낸 것으로 판정됩니다**
- 추출 결과는 **DB 가 아니라 파일로** 나옵니다. 사람이 보고 커밋할지 정합니다

### 3-2. `voh_max` 와 `io_level` 은 다릅니다

모듈 데이터시트는 Voh 규격(min/max)을 **잘 안 줍니다.** 대신 "IO level 3.3V" 라고 적습니다.
그걸 `voh_max` 에 적으면 **없는 규격을 있다고 말하는 것**입니다. 실제로 한 번 그렇게
적었다가 LLM 추출이 반박해서 항목을 나눴습니다. 규칙은 `voh_max` 를 먼저 보고 없으면
`io_level` 을 씁니다.

### 3-3. dedup 기준은 심각도가 아니라 **근거**입니다

`engine.dedupe()` 는 같은 네트에서 **새로운 근거를 하나도 못 내놓는** 발견만 합칩니다.

```
R11 + R12   둘 다 넷리스트 근거뿐   → 합친다
R12 + R08   R08 은 펌웨어 근거      → 둘 다 남는다
R12 + R04   R04 는 데이터시트 근거   → R12 가 R04 로 합쳐진다
```

**심각도로 고르면 안 됩니다.** 그렇게 만들었더니 차별 등급 R08 이 기본 등급 R12 에
먹혀 사라졌습니다 — 우리 차별점이 중복 정리에 지워졌습니다.

### 3-4. 보드와 칩은 다른 부품입니다

BOM 에는 `XIAO-ESP32C6`(보드), 데이터시트는 `ESP32-C6`(칩)으로 나옵니다.
사실 파일의 `applies_to_boards` 가 잇습니다. **핀 전기 특성만 물려받습니다**
(`facts.CHIP_INHERITED`) — `vcc_nominal` 은 뺐습니다. 보드에는 레귤레이터가 있어서
(XIAO 는 USB 5V → 칩 3.3V) 칩 전압을 보드 전압이라고 하면 **그 틀린 값으로
R11·R12 가 판정합니다.**

### 3-5. 계약의 `needs` 어휘는 아직 3개입니다

엔진 내부(`INPUT_NAMES`)는 `datasheet` 를 알지만, **카탈로그의 `needs` 에 쓰면
프론트가 모르는 값이 나갑니다.** R11·R12·R04 는 `datasheet` 를 **선택적으로** 봅니다 —
`needs` 에 안 적고 사실이 없으면 UNRESOLVED 로 둡니다. 이 방식을 따라 주세요.
정말 필요하면 **계약 → 프론트 타입 → 카탈로그** 순서입니다.

### 3-6. 규칙은 순수 함수입니다

`check()` 안에서 네트워크·LLM·파일 IO·시간·난수 금지 (헌법 2-1).
데이터시트 조회는 **러너가 이미 끝내서** `Context.datasheet` 에 넣어 줍니다.
규칙은 `rules/_clearance.py` 를 통해서만 사실을 봅니다.

## 4. main 머지하고 할 일

**먼저 `git pull` 하세요.** 위의 "이미 된 것"이 전부 main 에 있습니다.
브랜치를 바꾸면 `git status` 를 먼저 보세요 — 8/18 에 낡은 인덱스로 백엔드가
통째로 지워질 뻔한 일이 두 번 있었습니다.

### 1순위 — R02 · R03 · R09 (기본 등급, 셋이 같은 구조)

칩 표를 GPIO 로 잇는 같은 골격이라 **첫 하나를 만들면 나머지는 빨라집니다.**

| 규칙 | 무엇 | 표 |
|---|---|---|
| R02 | 회로도가 SPI flash 핀에 연결 | `docs/CHIPS.md` — ESP32-C6 GPIO24~30 |
| R03 | strapping 핀 부팅 상태 오류 | GPIO4·5·8·9·15 |
| R09 | 부팅 시 출력 나오는 핀에 부하 | 위와 같은 표 |

**착수 전에 알아야 할 것:** 우리 시연 보드(XIAO)는 **스트래핑 핀도 SPI 플래시 핀도
안 뽑아놨습니다.** 그래서 이 규칙들은 시연 보드에서 발견 0건입니다. 작동을 보이려면
**결함 주입 케이스를 같이 만들어야 합니다** (`scripts/make_injected.py` 에 추가).
그게 없으면 "구현했는데 아무 데서도 안 보이는" 상태가 됩니다.

**오탐 주의:** 스트래핑 핀을 **의도적으로** 쓰는 보드가 많습니다(GPIO8·9 를 알고 쓰는 경우).
`UNRESOLVED` 로 두고 "의도한 것이면 무시하세요"라고 말하는 쪽이 안전합니다.

### 2순위 — 결함 주입 케이스 늘리기

지금 7개(합성 6 · 실측 1)뿐이라 **숫자가 얇습니다.** 규칙을 하나 만들 때마다
양성·음성 케이스를 같이 넣어 주세요. `scripts/make_injected.py` 에 딕셔너리
하나 추가하고 다시 돌리면 됩니다.

```bash
python scripts/make_injected.py && python -m prefab --measure
```

**음성 케이스가 오탐율의 전부입니다** — 겉모습이 비슷한데 정상인 보드를 짝으로 두세요.

### 3순위 — R01 · R05 (차별 등급)

선행 조건은 다 있습니다. **R05 는 "무엇을 잡을지" 정의부터 필요합니다** —
"지원하지 않는 주변장치 조합"이 구체적으로 무엇인지 팀에서 정해야 합니다.

### 4순위 — F-1 GitHub Action

R10 을 기다리지 말고 **검사 결과를 커밋 간 diff** 하면 드리프트 서사가 완성됩니다.
새 인프라 0, 반나절 (`결정_기록.md` D-2).
