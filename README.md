## 무엇을 만드는가

대학상권 소상공인이 이미 가지고 있는 **POS 매출 데이터**를 분석하고,
**부산대 학사일정**과 결합해 다음 주 수요 변화를 예측하고 행동을 제안하는 서비스입니다.

사장님은 데이터를 매일 입력하지 않습니다. POS에서 내려받은 CSV를 **최초 1회** 올리면 됩니다.

```
POS 매출 데이터 + 학사일정 + 요일·시간 패턴
        ↓
   AI 매장 분석
        ↓
① 이번 주 분석  ② 다음 주 예측  ③ 놓친 기회 계산  ④ 홍보 콘텐츠
```

## 왜 필요한가

### 대학상권은 일반 상권과 다르게 움직입니다

일반 상권 분석 도구는 요일과 날씨를 봅니다. 대학상권은 여기에 **학사일정**이 더 크게 작용합니다.
개강, 시험, 종강, 방학, 축제 주기에 따라 수요가 크게 흔들립니다.

### 문제는 "모른다"가 아니라 "얼마나인지 모른다"입니다

사장님들은 시험 기간에 손님이 준다는 걸 경험으로 압니다.
모르는 것은 이쪽입니다.

- **얼마나** 줄어드는가 (감이 아니라 숫자)
- **언제** 다시 늘어나는가 (요일과 시간대까지)
- **어떤 메뉴**가 특히 흔들리는가
- 그래서 **얼마를 놓쳤는가**

STAFFI가 파는 것은 "몰랐던 사실"이 아니라 **감으로 알던 것의 정밀도**입니다.

## 핵심 차별점

| 구분 | 기존 | STAFFI |
|---|---|---|
| 범용 AI (ChatGPT 등) | 물어보면 답함. 우리 매장을 모름 | 매장 데이터를 지속 분석 |
| 영상 생성 AI | 사진 → 영상 | 매장 상황 분석 후 필요한 콘텐츠 생성 |
| POS·매출 분석 | 과거 매출 확인 | 과거 매출 + 학사일정으로 미래 예측 |
| 일반 상권 분석 | 요일·날씨 중심 | **학사일정 결합** |

### "그거 ChatGPT로 되지 않나요?"

문구 생성은 됩니다. 그래서 우리 차별점은 **AI가 글을 잘 쓰는 것이 아닙니다.**

```
ChatGPT
  "부산대 시험 끝나는데 카페 홍보 아이디어 줘"
  → 일반적인 아이디어

STAFFI
  → "이 매장은 시험 종료 후 금요일 16~19시 매출이 평균 18% 증가했고,
     그 시간대 아메리카노가 전체의 41%입니다.
     지난 3주 연속 목요일에 원두가 일찍 소진되었습니다."
```

**핵심 자산은 생성 AI가 아니라 축적되는 매장별 데이터와 학사일정의 결합입니다.**

## 기능

### ① 매출 분석 + 학사일정 기반 수요 예측 `1순위`

POS CSV를 업로드하면 자동으로 정리하고 분석합니다.

- 주간 매출, 전주 대비 증감
- 메뉴별 판매량, 요일·시간대 패턴
- 학사일정과 결합한 다음 주 예측
- **예측 근거를 항상 함께 표시** (숫자만 주지 않음)

```
예상 매출 ▲18%

근거
 · 최근 4주 매출 추세        ▲8%
 · 과거 시험 종료 직후 패턴   ▲10%
 · 금요일 매출 증가 경향      ▲5%
 · 강수 예보 반영            ▼5%
```

### ② 놓친 기회 계산 `1순위`

매출 증가 예측만으로는 행동이 바뀌지 않습니다. **손실을 금액으로 보여줍니다.**

> 지난주 목요일 아메리카노가 19시에 판매 종료되었습니다.
> 평소 마감까지 판매량 기준 **약 34만원의 판매 기회 손실**로 추정됩니다.
> 시험 종료 주 목요일은 3주 연속 같은 패턴입니다.

품절 시점을 POS 데이터에서 역산해 추정합니다. "매출 늘려드립니다"가 아니라 **"놓친 돈 보여드립니다"** 입니다.

### ③ 예측 검증 및 자기 교정 `1순위`

예측 서비스의 신뢰는 **틀렸을 때** 결정됩니다.

매주 예측과 실제를 대조하고, 어긋났으면 원인을 추적해 모델에 반영합니다.

> 지난주 예측 ▲18% / 실제 ▲4%
> 금요일 강수량을 반영하지 못했습니다.
> 강수 변수를 추가하고 유사 조건 과거 사례 3건을 재학습했습니다.

### ④ AI 홍보 콘텐츠 생성 `2순위`

분석 결과를 바탕으로 **무엇을 언제 홍보할지**까지 제안합니다.

- 홍보 시점 추천 (학사일정 기반)
- 릴스 대본 · 캡션 · 해시태그
- 사진 기반 숏폼 구성

단순 "사진 → 영상"이 아니라 `매장 데이터 → 학사일정 → 홍보 전략 → 콘텐츠` 흐름입니다.

### ⑤ 상권 벤치마크 `로드맵`

사장님이 절대 알 수 없는 정보 하나 — **옆 가게 상황**입니다.

> 이번 주 매출 ▲8%. 인근 카페 평균은 ▲15%였습니다.
> 시험 종료 특수를 상대적으로 덜 받으셨습니다.

익명 집계이므로 **점포 5~10곳 확보 후** 제공합니다. 데이터가 모일수록 강해지는 구조이며, 후발주자가 복제하려면 같은 상권 데이터를 처음부터 다시 모아야 합니다.

### ⑥ AI 전화 · 리뷰 · 일정 관리 `로드맵`

핵심 예측 기능이 안정된 후 확장합니다. MVP 범위에서 의도적으로 제외했습니다.

## 동작 흐름

```
[입력] POS CSV 업로드 (최초 1회)
   ↓
[1] 데이터 전처리
     · 메뉴명 정규화 ("아메" "아아" "ICE아메리카노" → 아메리카노)
     · 결측·이상치 처리, 휴무일 판별
   ↓
[2] 패턴 추출
     · 요일별 / 시간대별 / 메뉴별
     · 품절 추정 (평소 대비 이른 판매 종료 탐지)
   ↓
[3] 학사일정 결합
     · 개강 · 시험 · 종강 · 방학 · 축제 구간 매핑
   ↓
[4] 예측 생성
     · 규칙 기반 베이스라인 + 매장 개인화
     · 데이터 부족 시 예측하지 않고 명시
   ↓
[5] 근거 구성 ← 예측 수치와 항상 함께
   ↓
[6] 행동 제안
     · 발주 · 인력 · 홍보 시점
   ↓
[7] 콘텐츠 생성 (선택)
   ↓
[8] 사장님 확인 및 수정
   ↓
[9] 다음 주 실제값과 대조 → 오차 원인 분석 → 모델 반영
```

### AI가 판단하는 부분

- 제각각인 메뉴명을 같은 상품으로 묶을지
- 매출 하락이 수요 감소인지 품절인지
- 예측이 빗나간 원인이 무엇인지
- 이 매장이 학사일정에 민감한 유형인지

### 사람이 확인하는 부분

- 예측 결과 검토
- 홍보 콘텐츠 게시
- 발주·인력 결정 (에이전트는 제안만 함)

## 데이터

### 확보 방식

| 단계 | 방식 |
|---|---|
| MVP | POS에서 내려받은 CSV/엑셀 **최초 1회 업로드** |
| 상용화 | POS 업체 API 연동으로 자동 수집 |

**사장님 입력 최소화가 원칙입니다.** 매일 입력을 요구하는 서비스는 사용되지 않습니다.

### 데이터 보유량에 따른 제공 범위

| 보유 데이터 | 제공 |
|---|---|
| 없음 | 예측 제공하지 않음. 학사일정 캘린더와 상권 일반 정보만 |
| 1~3개월 | 요일·시간 패턴 분석. 예측은 참고 수준으로 명시 |
| 3~6개월 | 매장별 패턴 반영 |
| 6개월~ | 학사 이벤트별 변화 분석 |
| 1년~ | 전년 동기 비교 |

> 데이터가 없는 매장에 추측성 예측을 제공하지 않습니다.
> 첫 예측이 빗나가면 두 번째 기회가 없습니다.

### 데이터 정직성 원칙

이 프로젝트는 세 종류의 데이터를 사용하며, **화면과 발표에서 항상 구분해 표기합니다.**

| 종류 | 용도 | 표기 |
|---|---|---|
| 실측 (협력 점포 POS) | 패턴 검증, 정확도 측정 | 출처 명시 |
| 공공데이터 (유동인구 등) | 상권 단위 패턴 근거 | 출처 명시 |
| 예시 데이터 | 화면 시연, 개발 | **"예시 데이터" 표기 필수** |

**금지 사항**

- 가상 데이터로 "학사일정과 매출에 상관관계가 있다"를 증명하지 않습니다
  (우리가 넣은 패턴을 우리가 찾는 순환논리)
- 예시 수치를 실측처럼 제시하지 않습니다
- 검증되지 않은 시장 규모를 추정치 표기 없이 쓰지 않습니다

## 기술 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 프론트 | Next.js (App Router) + TypeScript | 한 프로젝트로 화면·API 라우트 처리 |
| 스타일 | Tailwind + shadcn/ui | 대시보드 컴포넌트 즉시 확보. 디자이너 없이 완성도 |
| 차트 | Recharts | 리포트가 차트 중심. React 친화적 |
| 백엔드 | FastAPI (Python) | 분석이 본체. pandas가 필요 |
| 분석 | pandas, statsmodels | 설명 가능한 예측 |
| DB | Supabase (PostgreSQL) | 인증·스토리지 포함. 세팅 부담 최소 |
| 파일 | Supabase Storage | CSV 원본 보관 |
| 배치 | Supabase Cron 또는 간단한 스케줄러 | 주간 분석 |
| LLM | Claude/GPT API | 메뉴 정규화 · 원인 분석 · 콘텐츠 생성 |
| 배포 | Vercel(프론트) + Railway(FastAPI) | 둘 다 무료 티어로 시작 |
| 알림 | 카카오 알림톡 또는 이메일 | 앱이 아니니 푸시 대신 |

> 규칙으로 풀리는 것은 LLM에 넣지 않습니다. 원가와 지연을 통제하기 위함입니다.

## MVP 범위

### 포함

- POS CSV 업로드 및 전처리
- 메뉴명 정규화
- 주간 분석 (매출·메뉴·요일·시간대)
- 학사일정 결합 다음 주 예측 + 근거 표시
- 품절 추정 및 놓친 기회 금액 산출
- 예측 대비 실제 대조 화면
- 홍보 콘텐츠 생성 (대본·캡션·해시태그)

### 제외 (의도적)

- 여러 POS 업체 실시간 API 연동
- 실시간 재고 관리 · 자동 발주
- 모든 업종에 대한 정교한 예측
- AI 전화 완전 자동화
- 상권 벤치마크 (데이터 부족)

> 하나의 흐름 — **실제 매출 → 학사일정 결합 → 예측 → 행동 제안** — 을
> 끝까지 작동시키는 것이 우선입니다.

## 검증 계획

### 검증해야 할 가정

- [ ] 학사일정과 실제 매출 사이에 유의미한 패턴이 존재하는가 **(Go/No-Go)**
- [ ] 사장님이 발주·재료량 결정을 실제로 어려워하는가
- [ ] "놓친 기회 금액"이 매출 증가율보다 설득력 있는가
- [ ] 실제 점포 1~2곳에서 6개월 이상 데이터를 확보할 수 있는가
- [ ] CSV 최초 1회 업로드를 받아들일 수 있는가
- [ ] 월 구독료 지불 의향이 있는가
- [ ] 상권 활성화 사업단이 외부 솔루션을 도입할 절차가 있는가

**첫 번째 항목이 이 프로젝트의 존폐를 결정합니다.** 패턴이 없으면 사업이 성립하지 않습니다.

### 실행 순서

```
1. POS 데이터 확보 요청 (점포 10곳 접촉 → 1~2곳 목표)
   접근: "무료로 매출 분석 리포트를 만들어 드리겠습니다"
   ※ "데이터 주세요"로 시작하면 거절됩니다. 대가가 있어야 합니다.

2. 공공데이터로 상권 패턴 선확인
   부산대역 승하차 인원 × 학사일정 중첩 그래프
   → 점포 데이터가 늦어져도 확보 가능한 근거

3. 사장님 인터뷰 5곳 이상
   발주 어려움 / 지불 의향 / 놓친 기회 체감 동시 확인

4. 실데이터 기반 정확도 측정
   예측 오차율 · 품절 탐지 정확도
```

### 성과 지표

- 예측 오차율 (MAPE)
- 품절 추정 정확도 (사장님 확인 대비)
- 놓친 기회 금액 추정의 체감 정확도
- 주간 리포트 열람률 · 제안 수용률
- 무료 → 유료 전환 의향

## 수익 모델

### 지불 구조

공실률이 높은 상권에서 개인 구독만으로는 확산이 어렵습니다.
**초기 결제 창구를 기관으로 설계합니다.**

| 단계 | 결제 주체 | 형태 |
|---|---|---|
| 0~1년 | 상권 활성화 사업단 · 지자체 | 상권 단위 B2G 도입 |
| 1~2년 | 정부 지원사업 공급기업 등록 | 사장님 자부담 최소화 |
| 2년~ | 점포 자비 구독 | 효과 체감 후 전환 |

### 가격 가설

| 플랜 | 가격 | 포함 |
|---|---|---|
| 기본 | 월 3~4만원대 | 분석 + 예측 + 콘텐츠 |
| 상권 | 별도 산정 | 기관용 상권 리포트 |

> 가격은 인터뷰로 검증할 **가설**입니다. 확정 수치가 아닙니다.

### 기관용 상권 리포트

지자체와 상권 활성화 사업단은 상권 데이터가 없어 사업 성과를 추정으로 보고합니다.
학사일정별 상권 매출 변동, 업종별 취약 시기, 행사 효과 측정을 제공합니다.

**사장님은 무료로 쓰고, 기관이 지불하는 구조**가 초기 확산에 유리합니다.

## 리스크

| 리스크 | 심각도 | 대응 |
|---|---|---|
| POS 데이터 확보 실패 | **최상** | 10곳 이상 접촉. 무료 리포트를 대가로 제시. 공공데이터로 상권 패턴 우선 확보 |
| 학사일정-매출 상관관계 미확인 | **최상** | 확인 즉시 방향 전환. 검증 없이 개발 진행하지 않음 |
| "사장님도 이미 안다"는 반론 | 높음 | 방향이 아니라 **크기·시점·메뉴 단위 정밀도**로 차별화. 놓친 기회 금액으로 프레이밍 |
| 침체 상권의 지불 여력 부족 | 높음 | B2G를 1차 결제 창구로 설계 |
| 초기 데이터 부족으로 예측 부정확 | 중간 | 데이터 없는 매장에는 예측을 제공하지 않음. 근거를 항상 함께 표시 |
| 범용 AI의 기능 흡수 | 중간 | 생성 기능이 아니라 매장별 데이터 축적을 자산으로 설정 |
| POS 사업자의 유사 기능 출시 | 중간 | 대학상권은 시장이 작아 우선순위가 낮음. 선점 후 데이터 축적 |
| 매출 데이터 민감성 | 중간 | 익명 처리, 최소 수집, 목적 명시. 벤치마크는 집계값만 사용 |
