## 병렬 분담

```
프론트 (강현)          백엔드 (담당자)
   │                      │
   ├ 1. 업로드 화면        ├ POST /uploads
   ├ 2. D-day             ├ GET /analysis/weekly
   ├ 4. 콘텐츠 화면        ├ GET /forecast
   │                      ├ GET /verification
   └───────┬──────────────┘
           ↓
      5. 연동 (lib/data.ts)
           ↓
      7. 시연 리허설
```

**충돌 주의** — `types/` 폴더는 계약이므로 양쪽이 동시에 고치지 않는다. 변경이 필요하면 PR로 올리고 상대에게 알린다.

## 시연 D-1 체크리스트

- [ ] `npm install && npm run dev`가 새 컴퓨터에서 되는가
- [ ] 4개 화면 + 3개 시나리오(`cafe` / `insufficient` / `stale`)가 전부 뜨는가
- [ ] 사이드바 6개 메뉴에 죽은 링크가 없는가
- [ ] 노트북 화면 해상도에서 큰 숫자가 잘리지 않는가
- [ ] 인터넷이 끊겨도 화면이 뜨는가 (Pretendard CDN 대비 로컬 폰트 여부)
- [ ] 3분 안에 동선이 끝나는가

## 가장 큰 리스크

1. **아직 실제 매장 데이터가 1건도 없다** — 지금 데이터는 가상 CSV다. 심사위원이 "실제 검증했나"를 물으면 답이 약하다. 점포 접촉이 개발보다 먼저다.
2. **인터넷 의존** — 폰트를 CDN에서 받는다. 시연장 와이파이가 불안하면 로컬 폰트로 바꿔야 한다.
3. **백엔드 미완성 상태로 시연할 가능성** — 목 데이터로도 시연은 되지만, "백엔드는 어디까지 됐나" 질문에 대비해야 한다.
