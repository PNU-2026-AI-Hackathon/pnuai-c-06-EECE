## 1. 한 줄 요약

**"강의실에서 식권을 사면, 걸어가는 시간이 곧 대기 시간"** — 부산대 금정회관
학식의 키오스크 줄과 배식 줄을 모바일 QR 식권 + 실시간 대기열로 없애는 앱.

## 3. 기술 스택 & 아키텍처

```
Flutter (Dart) ─ Riverpod 상태관리 ─ go_router 라우팅
   │
   ├─ Supabase: 카카오 OAuth 로그인 · DB 조회 · Realtime(실시간 대기열)
   ├─ Vercel API (백엔드 조우진): 식권 구매 · QR 검증 (위조 방지는 서버가)
   ├─ Google Gemini (무료 API): AI 메뉴 추천 (멀티턴 대화)
   ├─ 카카오 로컬 API: 부산대 주변 음식점 실데이터 (AI 컨텍스트)
   └─ 부산대 공식 식단 페이지 파싱: 금정회관 주간 실식단 자동 수집
```

**아키텍처 어필 포인트**: Repository 패턴으로 데이터 소스를 추상화 →
스위치 하나로 Mock(시연) ↔ 실서버 전환. 발표 중 네트워크가 죽어도
시연 모드로 즉시 폴백 가능 (데모 리스크 대비 설계).

## 4. 구현 완료 기능 (사용자 흐름 순)

### 학생 앱

1. **온보딩 3장** — 대기 확인 / QR 식권 / 자동 호출 컨셉 소개
2. **카카오 전용 로그인** — Supabase OAuth 연동, 회원가입 절차 없음 (실동작)
3. **홈 — 실시간 대기 현황**
   - 라인별(1층 정식/1층 일품/2층 교직원) 대기 인원·예상 시간·혼잡도 3단계
   - Supabase Realtime 구독 → 다른 사람이 구매하면 숫자가 실시간으로 움직임
   - pull-to-refresh, 스켈레톤 로딩, 시간대 인사말
4. **실제 금정회관 식단** — 부산대 공식 홈페이지를 파싱해 주간 중식/석식 자동 표시.
   가격도 실데이터(학생 5,000원/교직원 6,500원). **하드코딩 아님** —
   학교가 식단을 바꾸면 앱도 자동 반영. 17시 기준 중식↔석식 자동 전환
5. **모바일 QR 식권** — 구매 즉시 QR + 대기번호 발급 = 키오스크 줄 스킵.
   1회용 서버 토큰이라 캡처·재사용 부정 불가
6. **내 식권 / 이용 내역** — 상태(대기중/호출됨/사용완료) 실시간 갱신
7. **호출 알림** — 내 차례가 가까우면 인앱 + 백그라운드 푸시 알림
   (앱을 안 보고 있어도 울림)
8. **AI 메뉴 추천 "밥묵자 AI"**
   - 자연어 질문("오늘 매콤한 거 땡겨") → 실시간 혼잡도를 근거로 추천
   - 멀티턴 대화 (후속 질문 맥락 유지)
   - **주변 상권 연동**: 카카오 로컬 API로 부산대 정문 반경 800m 음식점
     실데이터를 컨텍스트에 주입 → 학식에 없는 메뉴면 주변 식당 추천 (도보 시간 포함)
   - 할루시네이션 방지: 데이터에 없는 식당·가격·대기시간은 답하지 않도록 설계

### 운영자(식당 직원) 대시보드

9. **LIVE 모드 (실서버)** — 라인별 실제 대기열 실시간 표시 (학생 앱 대기번호와
   동일 순번), 배식·호출·오늘 배식 수 집계
10. **카메라 QR 스캔** — 운영자 폰/태블릿 카메라로 학생 QR을 찍으면
    검증→사용완료→대기열 제거가 한 번에. **전용 스캐너 장비 불필요 (도입 비용 0원)**
11. **자동 운영 모드** — 배식 간격마다 자동 처리 (시연 연출용)
12. **Mock 시연 모드** — 서버 없이도 전체 흐름 시연 가능

## 5. 검증된 시연 시나리오 (폰 2대) ★발표 하이라이트

```
A폰(학생): 카카오 로그인 → 홈에서 혼잡도 확인 → 식권 구매 → QR·대기번호 발급
B폰(운영자): 대시보드에 A의 티켓이 실시간으로 뜸 → 카메라로 A폰 QR 스캔
A폰: 그 순간 "사용완료"로 실시간 전환
(+ 백엔드 called 전이 배포 시: 다음 대기자 폰에 호출 알림이 자동으로 울림)
```

- 구매→QR→대기번호→실시간 반영까지 **실서버로 E2E 검증 완료** (2026-07-13)
- 카메라 QR 스캔 실기기 동작 확인 (2026-07-14)

## 7. 로드맵 (발표 "향후 계획" 슬라이드용)

### 대기열 커버리지 3단계 (앱 미사용자 문제의 정직한 해법)
1. **Phase 1 (현재)**: 앱 대기열 + 시간대 패턴 기반 혼잡도 3단계 추정
2. **Phase 2**: 앱 전용 픽업 라인 분리 (사이렌오더 모델 — 미사용자 데이터 불필요)
3. **Phase 3**: 생협 키오스크 POS 연동 → 전체 대기열 100% 커버

### 주변 상권 3단계 (지역상권 활성화 = 창업 스토리)
1. **Phase A~B (현재 구현)**: 카카오 지도 실데이터 기반 AI 정보 추천 — 제휴 불필요
2. **Level 1 제휴**: 학생 쿠폰 (사장님 부담 0 — 장비·교육 없음)
3. **Level 2 제휴**: 원격 웨이팅 (사장님 폰 알림톡으로 — 태블릿 강요 안 함)
   → 수익모델: 피크타임 수요 분산 채널 → 노출 광고·제휴 수수료

## 8. 예상 Q&A (심사위원 질문 대비)

**Q. 앱 안 쓰는 학생은? 대기열이 섞이지 않나?**
→ 위 3단계 로드맵. 초기엔 혼잡도를 "정확한 분"이 아닌 3단계로 정직하게 표기,
파일럿 실측으로 보정 계수 학습, 최종은 POS 연동.

**Q. QR을 쓰는 이유는? NFC나 학생증은?**
→ ① 종이식권 대체(결제 증빙) ② 1회용 토큰이라 위조·재사용 차단
③ 스캔 = 배식 완료 이벤트 → 대기열 자동 제거·다음 호출의 시작점.
QR은 **추가 하드웨어 0원** (기존 태블릿/폰 카메라) — NFC 리더는 생협이 돈을 써야 함.

**Q. 식당(생협) 입장에서 뭐가 좋나?**
→ 직원 새 업무 0 (스캔 = 기존 검표 동작), 장비 투자 0, 시간대별 수요 데이터 확보,
키오스크 혼잡 해소. 협의 카드: "태블릿 한 대로 시작합니다."

**Q. 식단 데이터는 어디서?**
→ 부산대 공식 홈페이지 자동 파싱 (주간 중식/석식/가격). 생협 협의 전에도
실데이터로 서비스 가능함을 증명. 협의 후엔 품절·변경까지 운영자 화면에서 실시간.

**Q. AI가 잘못된 정보를 말하면?**
→ 실시간 혼잡도·실제 식단·카카오 실데이터만 컨텍스트로 주입하고,
데이터에 없는 것은 "모른다"고 답하게 설계 (할루시네이션 차단 규칙 적용·검증됨).

## 10. 시연 시 주의사항

- **시연은 안드로이드 실기기 기준** (웹은 CORS로 구매/주변상권 제한)
- 실행: `flutter run --dart-define-from-file=env.local.json` (플래그 필수)
- 서버 장애 시: 마이 탭 → 시연 모드 ON → Mock으로 전체 흐름 시연 가능
- 카카오 계정 2개 필요 (학생 A + 대기자 B 역할)
