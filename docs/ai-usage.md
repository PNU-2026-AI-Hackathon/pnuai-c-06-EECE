# AI 도구 활용 내역

**Prefab** · 창업트랙 C-06 전전컴 · 2026.08

## 1. 활용한 AI 도구

| 도구 | 어디에 |
|---|---|
| **Claude Code** (Opus 5) | 구현·리팩터링·테스트 작성 — **개발 도구로** |
| **Claude API** (Sonnet 5 / Opus 5) | 데이터시트 추출, 규칙 후보 발굴, 성능 비교 — **제품의 부품으로** |

**두 쓰임을 구분한다.** 앞은 우리가 코드를 짜는 데 쓴 것이고, 뒤는 제품 안에서 도는 것이다. 검증 방식이 서로 다르다.

## 2. 활용 범위

**개발 도구로서** — 커밋 대부분이 Claude Code 와 함께 작성됐다. 파서, 규칙 엔진 15개, 웹 화면, 배포 설정이 여기 해당한다. **설계 판단은 사람이 했다** — 무엇을 만들고 무엇을 안 만들지, 오탐을 어디까지 감수할지는 팀 결정이고 `apps/api/CLAUDE.md` 3·4절에 적혀 있다.

**제품의 부품으로서** — LLM 을 부르는 자리는 **셋뿐이고 전부 CLI 에서만 닿는다.** 웹 검사 경로에는 없다.

| 자리 | 하는 일 |
|---|---|
| `datasheet/extract.py` | PDF 에서 부품 사실 추출 |
| `discover/propose.py` | 우리 규칙이 못 본 결함 후보 제안 |
| `scripts/llm_baseline.py` | 성능 비교 실험 (제품 경로 아님) |

**판정 함수(`rules/*.py`)는 이 파일들을 import 하지 않는다.**

> LLM은 읽기만 한다. 판정은 코드가 한다. — 헌법 2-1

같은 파일을 넣으면 언제나 같은 결과가 나와야 하는 도구라서, 판정 경로에 확률적인 것을 두지 않았다.

## 3. AI 생성 코드의 검증·수정 방식

**걸어 둔 장치** — 규칙당 테스트 3개(양성·음성·미해결) · 실측 보드 골든 테스트 · **홀드아웃**(한 번도 안 본 남의 공개 보드) · 근거 문구 소스 스캔 · **인용문 원문 대조**(LLM 이 지어낸 출처를 막는다) · 머지 전 CI 확인. 테스트 파일 54개가 이 장치들을 들고 있다.

**실제로 걸러낸 것 — 발표했으면 틀렸을 숫자들**

- **과적합.** 오탐을 45 → 0 으로 줄였는데 **튜닝에 쓴 같은 보드 6개에서 쟀다.** 처음 보는 보드 38개에 대니 14건이 나왔다. 홀드아웃이 없었으면 「오탐 0」을 그대로 발표할 뻔했다.
- **가짜 개선.** 측정 스크립트가 `@property` 를 `()` 로 호출해 조용히 보드 5개를 결과에서 떨어뜨렸고, 개선처럼 보이는 숫자가 나왔다. 보드 목록을 앞뒤로 대조해 잡았다.
- **LLM 이 사람을 반박했다.** 팀원이 "IO level 3.3V" 를 `voh_max` 로 적었는데, 추출기가 `null` 과 함께 *"IO 레벨 표기이지 Voh 규격값이 아니다"* 라고 답했다. 매뉴얼을 확인하니 LLM 이 맞았고 항목을 나눠 고쳤다.
- **화면이 거짓말했다.** 「내 검사」가 *"주소를 아는 사람도 열 수 없습니다"* 라고 적고 있었다. 쿠키 없이 열어 보니 **열렸다.** 개인정보에 관한 문장이라 즉시 고쳤다.

**수정 방식** — 문제를 찾으면 **원인을 재현한 뒤에 고치고, 재발을 막는 테스트를 같이 넣는다.** 다만 측정 스크립트의 `@property` 오류는 사람이 눈으로 잡았고 **그 대조는 아직 자동화되지 않았다.** 이 문서가 검증에 관한 문서라서 적어 둔다.

---

**요약.** AI 로 빠르게 만들었지만 **판정 경로에는 AI 를 두지 않았고**, AI 가 만든 것을 사람과 테스트가 다시 쟀다. 그 과정에서 발표했으면 틀렸을 숫자를 여러 번 잡아냈다.
