# AI 도구 활용 내역

**Prefab** · 창업트랙 C-06 전전컴 · 2026.08

---

## 1. 활용한 AI 도구

| 도구 | 어디에 |
|---|---|
| **Claude Code** (Opus 5) | 구현·리팩터링·테스트 작성 |
| **Claude API** (Sonnet 5 / Opus 5) | **제품의 부품으로** — 데이터시트 추출, 규칙 후보 발굴, 성능 비교 실험 |

**두 쓰임을 구분한다.** 앞은 우리가 코드를 짜는 데 쓴 것이고, 뒤는 **제품 안에서 도는 것**이다. 검증 방식이 서로 다르다.

## 2. 활용 범위

### 2-1. 개발 도구로서

커밋 171개 대부분이 Claude Code 와 함께 작성됐다. 파서, 규칙 엔진 15개, 웹 화면, 배포 설정이 여기 해당한다.

**설계 판단은 사람이 했다.** 무엇을 만들고 무엇을 안 만들지(`apps/api/CLAUDE.md` 3·4절), 어느 규칙을 채택할지, 오탐을 어디까지 감수할지는 팀 결정이다.

### 2-2. 제품 안의 부품으로서

LLM 을 부르는 자리는 **셋뿐이고 전부 CLI 에서만 닿는다.** 웹 검사 경로에는 없다.

- `datasheet/extract.py` — PDF 에서 부품 사실 추출 (`--extract`)
- `discover/propose.py` — 우리 규칙이 못 본 결함 후보 제안 (`--discover`)
- `scripts/llm_baseline.py` — 성능 비교 실험 (제품 경로 아님)

**판정 함수(`rules/*.py`)는 이 파일들을 import 하지 않는다.** 헌법 2-1 이 그 선이다 —

> LLM은 읽기만 한다. 판정은 코드가 한다.

같은 파일을 넣으면 언제나 같은 결과가 나와야 하는 도구라서, 판정 경로에 확률적인 것을 두지 않았다.

## 3. AI 생성 코드의 검증·수정 방식

### 3-1. 걸어 둔 장치

| 장치 | 무엇을 막는가 |
|---|---|
| 규칙당 테스트 3개 (양성·음성·미해결) | 규칙이 반대 방향으로 도는 것 |
| 실측 보드 골든 테스트 | 리팩터링이 결과를 바꾸는 것 |
| **홀드아웃 측정** — 한 번도 안 본 남의 공개 보드 | **특정 보드에 맞춰 튜닝된 규칙** |
| 근거 문구 소스 스캔 테스트 | 사용자에게 나가는 문장의 조사·용어 오류 |
| 인용문 원문 대조 (`extract.py`) | **LLM 이 지어낸 출처가 DB 에 들어가는 것** |
| CI 초록불을 눈으로 확인 후 머지 | 저장소 관리자 권한이 없어 브랜치 보호를 못 건다 |

테스트 파일 54개가 이 장치들을 들고 있다.

### 3-2. 실제로 걸러낸 것

**과적합.** 오탐을 45 → 5 → 2 → 0 으로 줄였는데, **그 숫자를 튜닝에 쓴 같은 보드 6개에서 쟀다.** 처음 보는 보드로 두 번 다시 쟀다 — 10개에서 14건, 다시 28개에서 51건이 나왔다. 여기서 오탐 원인 6가지를 새로 찾아 고쳤다. 홀드아웃이 없었으면 "오탐 0" 을 그대로 발표할 뻔했다.

**가짜 개선을 보고할 뻔한 것.** 측정 스크립트에서 `@property` 를 `()` 로 호출해 `TypeError` 가 났고, 그게 조용히 보드 5개를 결과에서 떨어뜨렸다. 개선처럼 보이는 숫자(51 → 15)가 나왔다. **보드 목록을 앞뒤로 대조**해서 잡았다.

**LLM 이 사람을 반박한 것.** 팀원이 데이터시트의 "IO level 3.3V" 를 `voh_max` 로 적었는데, 추출기가 `null` 을 돌려주며 *"IO 레벨 표기이지 Voh 규격값이 아니다"* 라고 적었다. 매뉴얼에 Voh 표가 없는 것이 맞았고, **항목을 나눠 고쳤다.**

**칩 표를 넓게 잡아 생긴 오탐.** ESP32-C3 를 추가하자마자 치명 오탐 3건이 났다. SPI 플래시 전용 핀을 6개로 잡았는데 그중 2개는 쿼드 모드에서만 쓰인다. 실제 오픈소스 보드가 그 핀에 LED 를 달고 있었다. **4개로 좁혔다.**

**화면이 거짓말한 것.** 「내 검사」 화면이 *"주소를 아는 사람도 열 수 없습니다"* 라고 적고 있었다. 쿠키 없이 그 주소를 열어 보니 **열렸다.** 개인정보에 관한 문장이라 그대로 고쳤다.

### 3-3. 수정 방식

문제를 찾으면 **원인을 재현한 뒤에 고치고, 재발을 막는 테스트를 같이 넣는다.** 위 다섯 건 중 넷이 그렇다 — 예를 들어 ESP32-C3 플래시 핀은 `test_chip_identification.py` 가 `{14, 15, 16, 17}` 로 못 박고 있다.

**하나는 아직 테스트가 없다.** 측정 스크립트의 `@property` 오류는 사람이 보드 목록을 앞뒤로 대조해서 잡았고, 그 대조는 아직 자동화되지 않았다. 적어 두는 이유는 이 문서가 검증에 관한 문서이기 때문이다.

그리고 **못 한 일을 숨기지 않는다**(헌법 2-4). 규칙을 못 돌렸으면 결과에 사유가 그대로 실린다. AI 가 만든 코드가 조용히 빈 결과를 돌려주는 것이 이 제품에서 가장 위험한 실패라서, `blocked()` 규약을 따로 만들어 막았다.

---

**요약.** AI 로 빠르게 만들었지만, **판정 경로에는 AI 를 두지 않았고**, AI 가 만든 것을 사람과 테스트가 다시 쟀다. 그 과정에서 발표했으면 틀렸을 숫자를 여러 번 잡아냈다.
