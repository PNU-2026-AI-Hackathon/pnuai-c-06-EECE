# Prefab, 쉽게 읽는 설명서

> **누가 읽어도 되는 글입니다.** 전자공학을 모르셔도, 코딩을 안 해보셨어도 됩니다.
> 어려운 말이 나오면 바로 옆에 쉬운 말로 다시 적어 두었습니다.

---

## 1. 한 문장으로

**전자제품을 만들기 전에, 설계도와 프로그램이 서로 안 맞는 곳을 찾아 주는 도구입니다.**

---

## 2. 무슨 문제를 푸는 건가요

### 2-1. 전자제품은 두 개가 짝을 이룹니다

여러분이 쓰는 리모컨, 공기청정기, 로봇청소기 안에는 **초록색 판**이 들어 있습니다.
그 판 위에 부품들이 붙어 있고, 부품끼리 선으로 이어져 있습니다.

이걸 만들려면 **두 가지**가 필요합니다.

| | 쉬운 말로 | 어려운 말로 |
|---|---|---|
| ① | **어떤 부품을 어디에 이을지 그린 그림** | 회로도 · 넷리스트 |
| ② | **그 부품들에게 시키는 명령문** | 펌웨어 · 코드 |

**①은 몸이고 ②는 뇌입니다.** 둘이 짝이 맞아야 제품이 돕니다.

### 2-2. 짝이 어긋나면 어떻게 되나요

예를 들어 보겠습니다.

> 그림(①)에는 **버튼이 2번 자리**에 붙어 있습니다.
> 그런데 명령문(②)에는 **"4번 자리에 있는 버튼을 눌러라"** 라고 적혀 있습니다.

**4번 자리에는 아무것도 없습니다.** 그러면 버튼을 눌러도 아무 일도 안 일어납니다.

### 2-3. 그런데 왜 미리 못 찾나요

**여기가 이 문제의 진짜 무서운 점입니다.**

```
컴퓨터가 명령문을 검사합니다   →  "문법 이상 없음, 통과!"
제품에 프로그램을 넣습니다     →  "잘 들어갔습니다!"
```

**컴퓨터는 아무 말도 안 해 줍니다.** 왜냐하면 명령문 자체는 틀린 게 없거든요.
"4번 자리" 라고 쓴 것은 문법상 완벽합니다. **다만 그 자리에 아무것도 없을 뿐입니다.**

컴퓨터는 그림(①)을 안 봅니다. 그래서 모릅니다.

### 2-4. 그래서 언제 알게 되나요

**판을 진짜로 만들어서 손에 쥐어 봤을 때입니다.**

그런데 그 판은 공장에 주문해서 만듭니다. 여기서 문제가 생깁니다.

| 소프트웨어(앱, 웹사이트) | 하드웨어(전자판) |
|---|---|
| 틀리면 고쳐서 다시 올리면 끝 | **이미 만든 판은 버려야 합니다** |
| 몇 분 | **평균 8.5일** |
| 0원 | **한 번에 약 6,000만원** |

> **6,000만원이 뭐가 그렇게 비싼가요?**
> 판값만이 아닙니다. **엔지니어가 "왜 안 되지?" 하고 원인을 찾는 시간**이 제일 큽니다.
> 보통 40~80시간, 그러니까 **2주**가 통째로 사라집니다.
> (미국 조사 기준이라 우리나라에서는 금액이 더 작습니다. **하지만 2주가 날아가는 건 똑같습니다.**)

**저희는 판을 주문하기 전에 이걸 찾아 줍니다.**

## 3. 그럼 AI 한테 물어보면 되지 않나요

**제일 많이 받는 질문이라 실제로 재봤습니다.**

같은 전자판 28개를 놓고, 저희 도구와 최신 AI 를 나란히 돌렸습니다.

| | Prefab | 최신 AI |
|---|---|---|
| 끝까지 읽은 판 | **28개 전부** | 22개 (6개는 건너뜀) |
| 경고에 근거를 끝까지 댄 비율 | **100%** | 77% |

**AI 는 큰 판 6개를 아예 안 봤습니다.** 안 본 판은 "문제 없는 판"이 아니라 **"모르는 판"** 입니다.
그리고 낸 경고 중 일부에는 *"확인할 수 없다"* 가 섞여 있었습니다.

### 저희가 파는 것은 「똑똑함」이 아닙니다

**「똑같은 파일을 넣으면 언제나 똑같은 답이 나오는 것」입니다.**

AI 는 같은 걸 물어봐도 어제와 오늘 답이 다를 수 있습니다.
사람 대신 자동으로 돌아가는 검사에서는 **그게 치명적입니다.**

그래서 저희는 **판단하는 부분에 AI 를 아예 안 씁니다.**

```
AI 가 하는 일   :  설명서(PDF)에서 숫자 찾아 읽기, 새 규칙 후보 제안하기
AI 가 안 하는 일 :  "이건 잘못됐다" 라고 판단하기   ← 이건 사람이 짠 규칙이 합니다
```

## 4. 어떻게 찾아내나요 — 규칙 15개

저희는 **15가지 잘못**을 찾습니다. 사람이 하나하나 정한 규칙입니다.

### 4-1. 그림만 봐도 알 수 있는 것 (7가지)

이건 다른 회사 도구들도 합니다.

| 번호 | 쉬운 말로 |
|:---:|---|
| R02 | **건드리면 안 되는 자리**에 선을 이었습니다 (제품이 아예 안 켜집니다) |
| R03 | 켜질 때 방향을 정하는 자리를 **못 움직이게 묶어** 놨습니다 |
| R04 | **센 전기**를 견디는 한계보다 더 세게 흘려보내고 있습니다 (부품이 탑니다) |
| R09 | 켤 때 잠깐 신호가 나오는 자리에 **모터 같은 걸** 달았습니다 (켜자마자 움직입니다) |
| R11 | 선 이름은 3V 라고 써 놨는데 **실제로는 5V** 가 옵니다 |
| R12 | **센 전기와 약한 전기를 바로 이어** 놨습니다 |
| R17 | **한 자리에 선 두 개**가 물려 있습니다 (합선입니다) |

### 4-2. 그림과 명령문을 같이 봐야 알 수 있는 것 (8가지)

**여기가 저희만 하는 부분입니다.**

| 번호 | 쉬운 말로 |
|:---:|---|
| R01 | 명령문이 **이 부품에는 없는 자리**를 쓰라고 합니다 |
| R05 | 이 부품이 **동시에 못 하는 일 두 개**를 같이 시키고 있습니다 |
| **R07** | **명령문은 쓰는데 그림에는 안 이어져 있습니다** ← 2-2의 그 상황 |
| **R08** | **그림에는 이어져 있는데 명령문이 안 씁니다** (달아 놓고 안 씀) |
| **R10** | **그림을 고쳤는데 명령문이 안 따라왔습니다** |
| R14 | 같은 이름이 **파일마다 다른 자리**를 가리킵니다 |
| **R15** | 신호가 **너무 약해서 상대 부품이 못 알아듣습니다** |
| R16 | 안전한 값을 넣기 **전에** 전원을 켜서, **켤 때마다 잠깐 움직입니다** |

> **R15 는 저희 팀에서 실제로 있었던 일입니다.**
> 팀원이 만든 판에서 **LED 가 켜지는데 안 꺼졌습니다.**
> 신호가 너무 약해서 상대 부품이 "꺼져"를 못 알아들은 거였습니다.
> 그 일이 규칙이 됐습니다.

### 4-3. 규칙을 「안 만든」 이야기

규칙 번호는 R17까지 가는데 규칙은 15개입니다. **두 개를 버렸기 때문입니다.**

- **R06** — 다른 회사가 이미 똑같은 걸 하고 있어서 안 만들었습니다.
- **R13** — 하드웨어 담당이 **"이건 실제로 위험하지 않다"** 고 해서 안 넣었습니다.

**위험하지 않은 것을 규칙으로 만들면, 멀쩡한 제품에 자꾸 "잘못됐다"고 소리치게 됩니다.**
그러면 사람들이 이 도구를 꺼 버립니다. **그래서 규칙을 늘리는 것보다 빼는 게 더 중요합니다.**

## 5. 저희의 본질 — 지키기로 한 네 가지

이게 저희가 다른 도구와 다른 이유입니다.

### ① AI 는 읽기만 하고, 판단은 사람이 짠 규칙이 합니다
같은 파일을 넣으면 **언제나 같은 답**이 나옵니다. 어제와 오늘이 다르면 못 믿습니다.

### ② 모르면 모른다고 합니다
부품이 뭔지 모르겠으면 **"모르겠다"** 고 화면에 그대로 씁니다.
**대충 넘어가서 "통과!" 라고 하지 않습니다.**

### ③ 잘못 짚는 것이 제일 나쁩니다
멀쩡한데 "잘못됐다"고 하면 사람들이 **3일 만에 이 도구를 끕니다.**
그래서 못 찾는 것보다 **잘못 짚는 것**을 더 무서워합니다.

### ④ 못 한 일을 숨기지 않습니다
부품 목록이 없어서 규칙 하나를 못 돌렸으면, **"못 돌렸습니다" 라고 화면에 씁니다.**

> **이 넷을 지키다가 저희가 스스로에게 걸린 적이 있습니다.**
>
> 잘못 짚는 걸 45번에서 0번까지 줄이고 좋아했는데, 알고 보니
> **연습에 쓴 것과 똑같은 판 6개**로 시험을 보고 있었습니다.
> 처음 보는 판 38개에 다시 돌리니 **14번**이 나왔습니다.
> 그걸 고쳐서 지금은 **1번**입니다. **0이라고 안 씁니다.**

## 6. 어떻게 쓰나요 — 방법 1 : 웹에서 (제일 쉬움)

### 준비물

**없습니다.** 회원가입도 안 해도 됩니다. (체험 1회가 열려 있습니다)

### 순서

**1단계.** 인터넷 주소창에 이걸 칩니다

```
https://prefab-web.onrender.com
```

**2단계.** 「지금 검사해 보기」 를 누릅니다

**3단계.** 파일 3개를 끌어다 놓습니다

| 넣는 것 | 쉬운 말로 | 파일 이름이 이렇게 생겼습니다 |
|---|---|---|
| 회로도 | **부품 연결 그림** | `board.net.xml`, `board.net` 등 |
| 펌웨어 | **명령문** | `firmware.zip` (폴더를 압축한 것) |
| 부품표 | **부품 목록** (없어도 됨) | `bom.csv` |

> **파일이 없으신가요?** 화면에 **「샘플 보드로 해보기」** 버튼이 있습니다.
> 누르면 예시 파일이 자동으로 채워집니다.

**4단계.** 「검사 실행」 을 누르고 **10초쯤** 기다립니다

**5단계.** 결과를 봅니다

```
치명  2건    ← 이건 꼭 고쳐야 합니다. 안 고치면 제품이 안 됩니다
경고  1건    ← 고치는 게 좋습니다
해제됨 1건   ← 문제인 줄 알았는데 확인해 보니 괜찮았습니다
```

### 결과 화면에서 꼭 보셔야 할 것

**① 발견 카드를 펼치면 「왜 그렇게 판단했는지」가 나옵니다**

```
회로도에서  →  몇 번째 줄을 봤는지
명령문에서  →  어느 파일 몇 번째 줄을 봤는지
부품에서    →  설명서 어느 값을 봤는지
```

**AI 가 그럴싸하게 말한 게 아닙니다. 진짜로 그 줄을 보고 판단한 겁니다.**

**② 아래로 내리면 「어디까지 봤나」가 있습니다**

```
부품 12개 중 4개만 알아봤습니다
나머지 8개는 모릅니다
```

**모르는 걸 모른다고 적어 놓은 자리입니다.** 이게 저희가 제일 자랑스러워하는 화면입니다.

## 7. 어떻게 쓰나요 — 방법 2 : 자동으로 (GitHub 연동)

### 이게 왜 필요한가요

방법 1은 **사람이 기억해서 직접 올려야** 합니다. 그런데 사람은 잊어버립니다.

**방법 2는 잊어버릴 수가 없습니다.** 누가 그림이나 명령문을 고치면 **자동으로 검사가 돕니다.**
그리고 문제가 있으면 **아예 반영이 안 되게 막습니다.**

> **GitHub 이 뭔가요?**
> 프로그램 파일을 여럿이 같이 보관하고 고치는 사이트입니다.
> 구글 드라이브 비슷한데, **누가 언제 뭘 고쳤는지 전부 기록**된다는 게 다릅니다.
>
> **PR(피알) 이 뭔가요?**
> "제가 이렇게 고쳤는데 반영해도 될까요?" 하고 **올리는 신청서**입니다.
> 다른 사람이 확인하고 「반영」 버튼을 눌러야 진짜로 들어갑니다.

### 제일 쉬운 길 — 자동으로 붙이기

**1단계.** 이 주소로 갑니다

```
https://prefab-web.onrender.com/connect
```

**2단계.** 「GitHub 으로 연결하기」 를 누릅니다

**3단계.** 저장소를 고릅니다

그러면 저희가 **저장소를 훑어서 그림·명령문·부품표가 어디 있는지 찾아 줍니다.**

> **확신이 없으면 저희는 비워 둡니다.**
> 틀린 위치를 적어 두는 것이 빈칸보다 나쁘기 때문입니다.

**4단계.** 저희가 **PR 을 하나 올려 드립니다.** 그걸 반영하면 설정 끝입니다.

### 마지막 한 걸음 — 열쇠 넣기 (이건 직접 하셔야 합니다)

**왜 직접 하셔야 하나요?**
저희가 대신 넣으려면 **여러분 저장소의 모든 비밀번호를 바꿀 수 있는 권한**을 받아야 합니다.
**그 권한은 안 받는 게 맞다고 봤습니다.**

**① 열쇠(API 키)를 만듭니다**

```
https://prefab-web.onrender.com  →  로그인  →  「내 검사」  →  「키 만들기」
```

만들면 `prefab_xxxxx...` 같은 긴 글자가 나옵니다. **이 창을 닫으면 다시 못 봅니다.** 복사해 두세요.

**② 그 열쇠를 GitHub 에 넣습니다**

컴퓨터의 **터미널**(검은 창)에 이걸 칩니다:

```bash
gh secret set PREFAB_API_KEY --repo 내계정이름/저장소이름
```

**엔터를 치면 열쇠를 물어봅니다. 그때 붙여 넣으세요.**

> **왜 명령어에 열쇠를 같이 안 쓰나요?**
> 명령어에 직접 적으면 **컴퓨터가 그걸 기록으로 남깁니다.**
> 나중에 누가 그 기록을 보면 열쇠가 그대로 보입니다.

**터미널이 어려우시면** 이렇게 해도 똑같습니다:

```
GitHub 저장소  →  Settings  →  Secrets and variables  →  Actions
             →  New repository secret
             →  이름 칸에  PREFAB_API_KEY
             →  값 칸에   복사해 둔 열쇠
```

### 손으로 직접 붙이려면

`.github/workflows/prefab.yml` 이라는 파일을 만들고 아래를 넣습니다.

```yaml
name: 회로도 ↔ 코드 대조
on:
  pull_request:
    paths: ["hardware/**", "firmware/**"]

jobs:
  prefab:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: PNU-2026-AI-Hackathon/pnuai-c-06-EECE/.github/actions/prefab-check@main
        with:
          api-key: ${{ secrets.PREFAB_API_KEY }}
          netlist: hardware/board.net.xml
          firmware: firmware/
          # bom: hardware/bom.csv        없어도 됩니다
          # fail-on: critical            critical | warning | never
```

**이 파일이 하는 말을 한 줄씩 풀면 이렇습니다:**

| 줄 | 무슨 뜻인가요 |
|---|---|
| `on: pull_request` | **누가 반영 신청서를 올릴 때마다** |
| `paths: [...]` | **그림이나 명령문이 바뀐 경우에만** (다른 건 신경 안 씀) |
| `netlist:` | 그림 파일이 **어디 있는지** |
| `firmware:` | 명령문이 **어느 폴더에** 있는지 |
| `fail-on: critical` | **꼭 고쳐야 할 게 나오면 막아라** |

### 그래서 어떻게 되나요

```
누가 그림을 고치고 신청서를 올린다
        ↓  (10초쯤)
검사가 자동으로 돈다
        ↓
문제가 있으면  →  🔴 빨간불  →  「반영」 버튼이 회색으로 잠깁니다
문제가 없으면  →  🟢 초록불  →  「반영」 버튼이 파랗게 살아납니다
```

**사람이 리뷰에서 놓쳐도 들어갈 수가 없습니다.**

## 8. 얼마인가요

| | 값 | 무엇이 되나요 |
|---|---|---|
| **무료** | 0원 | 웹에서 **검사 무제한** · 근거 보기 · 결과 링크로 공유 |
| **Pro** | 9,900원 / 월 | **자동 검사(위 7번)** · 반영 막기 |
| **팀** | 39,000원 / 월 | 회사 계정 · 회사만의 부품·규칙 등록 |

### 왜 무료가 무제한인가요

**검사 한 번에 드는 돈이 거의 0원이기 때문입니다.**

판단하는 부분이 **사람이 짠 규칙**이라서, 검사할 때 **AI 를 안 부릅니다.**
AI 를 부르면 부를 때마다 돈이 나가는데, 저희는 안 나갑니다.

### 지금은 결제가 안 됩니다

아직 사업자등록 전이라 카드 결제를 못 받습니다.
**그래서 지금은 Pro 기능도 다 열어 두었습니다.** 홈페이지에도 그렇게 적어 놨습니다.

## 9. 자주 나오는 질문

**Q. 제 설계도를 서버에 올리는데 안전한가요?**
올린 파일을 **하드디스크에 저장하지 않습니다.** 검사하고 바로 버립니다.
그리고 그게 진짜인지 **코드로 확인해 두었습니다.**
(처음엔 이 말이 사실이 아니었습니다. 큰 파일은 몰래 저장되고 있었고, 찾아서 고쳤습니다.)

**Q. 어떤 부품을 지원하나요?**
지금은 **6종류**입니다 — ESP32, ESP32-C3, C6, H2, S3, RP2040.
**이 목록에 없는 부품은 "모른다"고 답합니다.** 아는 척하지 않습니다.

**Q. PCB 랑 뭐가 다른가요?**
**PCB** 는 부품을 **어디에 놓을지** 정하는 것이고, 저희가 보는 **넷리스트**는 **무엇과 무엇을 이을지** 입니다.
배치는 공장이 무료로 봐 줍니다. **"이은 게 명령문과 맞는지"는 아무도 안 봅니다.**

**Q. 판을 안 만들어도 되나요?**
네. **그림 파일 하나만 있으면 됩니다.** 판을 뜨기 전에 쓰라고 만든 도구입니다.

**Q. 잘못 짚으면 어떡하죠?**
**처음 보는 판 38개에서 1건 남아 있습니다.** 0이라고 안 씁니다.
저희가 어디서 틀리는지는 여기 적어 뒀습니다 → https://prefab-web.onrender.com/evidence
