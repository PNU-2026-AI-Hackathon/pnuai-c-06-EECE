# Prefab Web

[Prefab](../prefab-api)의 프론트엔드. 회로도와 펌웨어를 올리면 검사 결과를 보여줍니다.

판정 로직은 전부 [`prefab-api`](../prefab-api)에 있습니다. 이 저장소는 화면만 담당합니다.

---

## 화면

| 라우트 | 역할 |
|---|---|
| `/` | 업로드 — 넷리스트(필수) · BOM(선택) · 펌웨어(선택) |
| `/c/{id}` | 처리 중 — 파이프라인 7단계 진행 |
| `/r/{id}` | 리포트 — 요약 · 발견 목록 · 넷리스트 부록 |

결과는 **URL만으로 열립니다.** 로그인이 없습니다.

---

## 디자인

**토스 계열 톤** — 흰 표면 · 넓은 여백 · 부드러운 라운드 · 얇은 회색 선.

시그니처는 발견 카드의 **소스 레인 3줄**입니다.
회로도 / 코드 / 데이터시트가 각각 한 줄을 갖고, 세로축은 "누가 말했는가" 하나만 뜻합니다.
채운 점 ●은 우리가 읽은 사실, 빈 고리 ○은 아직 모르는 것입니다.
회로도 줄과 코드 줄 사이를 지나는 빨간 이음매가 어긋남이 생기는 자리입니다.
제품의 논지가 곧 레이아웃입니다.

> **색·폰트·라운드 값은 여기에 적지 않습니다.**
> 진실은 [`tailwind.config.js`](./tailwind.config.js) 하나이고,
> 규약은 [`CLAUDE.md` 5절](./CLAUDE.md)에 있습니다.
> 문서에 값을 복사해 두면 반드시 어긋납니다. 실제로 한 번 어긋났습니다.

리포트 구조는 Chrome Lighthouse를 참고했습니다 — 요약 → 심각도별 발견 → 근거 → 수정 방법,
그리고 "해제됨" 항목은 접어서 하단에 둡니다.

## 빠른 시작

```bash
pnpm install
cp .env.example .env        # VITE_API_BASE 설정
pnpm dev                    # http://localhost:5173
```

`VITE_API_BASE`를 비워두면 목 데이터로 동작합니다. 백엔드 없이 화면 작업을 할 수 있습니다.

목은 두 벌입니다. **URL로 골라서 엽니다.**

| 주소 | 무엇 |
|---|---|
| `/r/chk_sample01` | `src/mocks/check.json` — 실제 `.d356`을 파서·규칙 엔진에 돌린 결과 (R11 · R12) |
| `/r/chk_target01` | `../../docs/examples/check.target-with-firmware.json` — **목표 응답 명세** (R7 · R8 · R13 포함) |

두 번째는 **실제 검사 결과가 아닙니다.** 계약 예시 파일을 사본 없이 그대로 읽고,
리포트 맨 위에 그 사실을 띄웁니다. 여기 숫자를 인용하지 마세요.

백엔드가 R7·R8을 내놓기 전에 **코드 레인이 채워진 발견 카드**를 보기 위한 것입니다 —
회로도 레인과 코드 레인이 둘 다 찬 상태가 이 제품의 얼굴인데,
첫 번째 목만으로는 코드 레인이 영원히 비어 있습니다.

```bash
pnpm build && pnpm preview
```

## 원칙

**숫자를 지어내지 않습니다.** API가 0을 주면 0으로 표시하고, `null`은 `—`로 둡니다.
미구현 기능은 "미구현"이라고 씁니다.

**못 한 일을 숨기지 않습니다.** BOM이 없어서 데이터시트 단계를 건너뛰었으면
그 사실과 사유를 화면에 그대로 보여줍니다. 흐리게 처리하거나 감추지 않습니다.
무엇을 못 했는지 보이는 것이 이 제품의 신뢰입니다.
