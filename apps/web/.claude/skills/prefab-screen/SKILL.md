# Prefab 화면 작업

이 저장소의 화면은 **"우리가 무엇을 알고 무엇을 모르는가"를 파는 제품**이다.
그래서 예쁘게 만드는 것보다 **거짓말을 안 하는 것**이 우선이다.

디자인 값·화면 목록·발견 카드 규약은 [`apps/web/CLAUDE.md`](../../../CLAUDE.md)에 있다.
이 스킬은 거기 없는 것 — **절차**를 다룬다.

---

## 0단계 — 계약을 먼저 읽는다

[`docs/API_CONTRACT.md`](../../../../../docs/API_CONTRACT.md)와 `src/types/api.ts`를 연다.
**화면이 쓰려는 값이 계약에 있는지부터 확인한다.** 없으면 3단계로 간다 — 지어내지 않는다.

---

## 1단계 — 문장 감사 (제일 중요하다. 건너뛰지 말 것)

화면에 새로 뜨는 **한국어 문장 하나하나에 대해** 묻는다.

> **이 문장이 참이라는 걸 응답의 어느 필드가 보장하는가?**

답이 "대체로 그렇다"거나 "지금 목에서는 맞다"면 **그 문장은 틀렸다.**

이 저장소는 이 실수를 이미 **네 번** 했다. 전부 같은 모양이다 —
*일부만 참인 문장을 전체에 대해 단언한 것.*

| 언제 | 화면이 한 말 | 왜 거짓이었나 |
|---|---|---|
| 업로드 | `"코드 대조 규칙 5개 실행 불가"` | 규칙 수를 하드코딩. 규칙이 늘면 즉시 거짓 |
| 발견 카드 | `"모름"` | 펌웨어를 **읽었는데** 이 판정에 안 썼을 뿐인 경우까지 "모름"이라 함 |
| 리포트 요약 | `"규칙 N개는 입력이 부족해 실행하지 못했습니다"` | 대부분은 입력이 아니라 **미구현**이라 못 돈 것 |
| R08 카드 | `"이 판정은 코드를 근거로 쓰지 않았습니다"` | R08의 판정 근거가 **바로 그 코드**다. 카드가 자기 판정을 부정 |

**감사 방법** — 문장에 수량사나 원인이 들어 있으면 반드시 쪼갠다.

- "N개" → 그 N은 어느 필드에서 왔나? 카탈로그가 없으면 **개수를 말하지 않는다**
- "~때문에" → 원인이 한 종류라고 가정하고 있지 않나? (입력 부족 / 미구현 / 해당 없음은 다 다르다)
- "~하지 않았습니다" → 정말 안 한 건가, 아니면 **했는데 근거로 안 실린 건가**
- "없습니다" → 못 찾은 건가, 안 찾은 건가, 찾을 수 없는 건가

구분이 안 되면 그건 화면 문제가 아니라 **계약 문제**다. 3단계로 간다.

---

## 2단계 — 만든다

- 색·폰트·라운드 값은 `tailwind.config.js`에서 온다. **문서나 코드에 값을 복사하지 않는다.**
- 응답 타입은 `src/types/api.ts`에 계약 그대로. 화면에서 변형하지 않는다.
- 계약에 없는 파생값이 필요하면 컴포넌트가 아니라 `src/lib/`에 함수로 둔다
  (`CheckResult`에 필드를 얹지 않는다 — 백엔드가 붙는 날 그게 거짓이 된다).
- `skipped`·빈 값·모르는 것을 **흐리게 하거나 접지 않는다.** 그게 이 제품의 신뢰다.

---

## 3단계 — 계약에 없으면 요청서에 적는다

계약을 혼자 고치지 않는다. [`_docs/백엔드_요청서.md`](../../../../../_docs/백엔드_요청서.md)에
**무엇이 없어서 무엇을 못 하는지** 적는다. 다음 세 가지를 반드시 함께 쓴다.

1. 지금 화면이 어떻게 처리하고 있는지 (그리고 그게 왜 약한지)
2. 어떤 모양으로 오면 되는지 — **JSON 예시로**
3. 그게 없어도 화면이 안 깨지는지

넓히는 변경(필드 추가, `number` → `number | null`)은 기존 응답을 깨지 않으므로
계약과 목표 응답 예시에 먼저 반영하고 요청서에 "이렇게 고쳐뒀습니다"라고 알린다.
**좁히는 변경은 백엔드 답을 받고 한다.**

---

## 4단계 — 실제로 렌더해서 본다 (필수)

목이 두 벌이다. **둘 다 연다.** 하나만 보면 절반은 검증이 안 된다.

```
/r/chk_sample01   실제 검사 결과 (R11 · R12) — 코드 레인이 항상 비어 있다
/r/chk_target01   목표 응답 명세 (R7 · R8 · R13) — 코드 레인이 채워진 유일한 경로
```

id는 각 JSON의 `check_id`다. **외우지 말고 파일에서 확인한다** — 계약 문서의 예시 id
(`chk_7f3a2b`)와 다르다.

두 번째는 `docs/examples/check.target-with-firmware.json`을 사본 없이 읽는다.
**실제 검사 결과가 아니므로** 리포트 맨 위에 그 사실이 뜬다. 이 배너를 지우지 않는다.

확인할 것:

- [ ] 두 목 모두에서 새 문장이 참인가 (1단계 감사를 화면에서 재확인)
- [ ] 발견 카드 세 레인의 상태가 맞는가 — `읽음` / `근거 없음` / `모름`
- [ ] 회로도 레인과 코드 레인 사이 **빨간 이음매**가 살아 있는가
- [ ] 375px에서 가로 스크롤이 안 생기는가 (`document.documentElement.scrollWidth <= innerWidth`)
- [ ] 콘솔 에러 0

브라우저 프리뷰의 뷰포트가 0으로 잡히면 `getBoundingClientRect`가 전부 거짓말을 한다.
**측정 전에 뷰포트를 명시적으로 지정한다.**

## 5단계 — 보고

```
발견 카드 R08 코드 레인 수정
  고친 것  : "근거로 쓰지 않았습니다" → 부재를 근거로 표시
  계약 변경: firmware evidence 의 line 을 number | null 로 넓힘 (요청서 2-5)
  확인     : /r/chk_target01 · /r/chk_7f3a2b · 375px · tsc 통과
  남은 것  : 백엔드 답변 대기 (line: null 수용 여부)
```

## 하지 말 것

- 계약에 없는 필드를 `CheckResult`에 얹는 것
- 목에서만 참인 문장을 화면에 쓰는 것
- 디자인 값을 문서·주석·다른 컴포넌트에 복사하는 것
- `skipped`·`null`·"모름"을 흐리게 하거나 접어서 감추는 것
- 렌더해 보지 않고 "고쳤습니다"라고 말하는 것
- 마케팅 섹션·차트 라이브러리·상태관리 라이브러리·다크 모드
  (범위 밖. [`CLAUDE.md`](../../../CLAUDE.md) 6절)
