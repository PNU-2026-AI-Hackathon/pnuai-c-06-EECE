# Prefab Web — 프로젝트 헌법

이 저장소에서 작업하는 모든 세션은 이 파일을 먼저 읽는다.

**저장소 역할**: 화면만. 판정 로직은 전부 `prefab-api`에 있다.
**마감**: 2026-08-28 최종 발표.
**배포는 최우선이 아니다.** 화면과 규칙이 먼저고, 배포는 붙일 준비만 해둔다
(`VITE_API_BASE`가 비면 목 데이터로 돈다).

---

## 1. 이 제품이 하는 일

> **이미 짜놓은 펌웨어가 바뀐 회로도를 따라가고 있는지 검사한다.**
> 회로도 · 펌웨어 · 부품 데이터시트를 함께 읽고, 셋 사이의 어긋남을 보드 발주 전에 잡는다.

화면이 전달해야 하는 것은 하나다 — **회로도가 말하는 것과 코드가 말하는 것이 서로 다르다.**
레이아웃 자체가 이 논지를 보여줘야 한다.

---

## 2. 절대 규칙

### 2-1. 숫자를 지어내지 않는다

API가 `0`을 주면 `0`으로 표시한다. `null`이면 `—`로 표시한다.
**placeholder 수치를 넣지 않는다.** ("부품 DB 418개" 같은 값은 과거 목업의 잔재이며 금지)
미구현 기능은 "미구현"이라고 쓴다. 그럴듯하게 채우지 않는다.

### 2-2. 못 한 일을 숨기지 않는다

`pipeline[].status === "skipped"` 인 단계를 흐리게 처리하거나 접어서 감추지 않는다.
사유(`detail`)를 그대로 노출한다. **무엇을 못 했는지 보이는 것이 이 제품의 신뢰다.**

### 2-3. 계약을 임의로 확장하지 않는다

`API_CONTRACT.md`에 없는 필드를 가정하지 않는다. 필요하면 백엔드 담당과 함께 계약을 고친다.

## 3. 화면 3개

| 라우트 | 역할 |
|---|---|
| `/` | 업로드 — 슬롯 3개(넷리스트 필수 / BOM 선택 / 펌웨어 선택) + "샘플 보드로 실행"※ |
| `/c/{check_id}` | 처리 중 — `pipeline` 배열을 순서대로 표시, 1초 폴링 |
| `/r/{check_id}` | 리포트 — 요약 → 입력 → 발견 목록 → 넷리스트 부록 |

※ "샘플 보드로 실행"은 **목 모드에서만** 뜬다. 샘플은 목이 아는 검사라서
서버가 붙으면 404 가 난다. 서버가 샘플 검사를 직접 만들어 주면 되살린다 (백엔드_요청서 F-4).

리포트 구조는 **Chrome Lighthouse 리포트**를 따른다.
`verdict === "PASS"`(해제됨) 항목은 Lighthouse의 "통과한 감사"처럼 **접어서 하단에** 둔다.

업로드 화면에서 선택 항목이 비면 `warn` 색으로 **무엇을 못 하게 되는지** 명시한다.
- BOM 없음 → "부품 식별 불가 · 오탐 증가"
- 펌웨어 없음 → "코드 대조 규칙 5개 실행 불가"

## 4. 시그니처 컴포넌트 — 발견 카드

**제품의 얼굴이다. 여기에 공을 들인다.**

**소스마다 한 줄(레인)을 준다.** 세로축은 "누가 말했는가" 하나만 뜻한다.
가로축에 다른 의미를 겹치지 않는다 — 그게 이 카드의 유일한 규칙이다.

```
┌──────────────────────────────────────────────────────┐
│ [치명] R12  상위 전원 도메인이 하위를 직결           │
│ PRESENCE_3V3                        [기본] [어긋남]  │
├──────────────────────────────────────────────────────┤
│ 5V로 동작하는 부품의 출력이 3.3V 핀에 …              │
├──────────────────────────────────────────────────────┤
│ ● 회로도가 아는 것 │ U2.OUT → PRESENCE_3V3 …         │
│ │  읽음           │                                  │
├═════════════════════════════════════════════════════─┤ ← crit 1.5px 이음매
│ ○ 코드가 아는 것   │ 펌웨어를 올리면 이 줄이 채워집니다 │
│ ┊  모름           │                                  │
│ ○ 데이터시트가…    │ BOM을 올리면 …                   │
├──────────────────────────────────────────────────────┤
│ 판정 보류 사유 / 해제 근거 / 다음 단계               │
└──────────────────────────────────────────────────────┘
```

- 레인 3개(`netlist` · `firmware` · `datasheet`)는 **근거가 없어도 지우지 않는다.**
  빈 레인이 곧 "무엇이 있어야 판정이 되는가"다. 접거나 흐리게 하지 않는다.
- 왼쪽 마디와 레일이 소스의 상태다 — **채운 점 ● + 실선 = 읽은 사실 /
  빈 고리 ○ + 점선 = 아직 모름.** 같은 기호를 업로드 슬롯과 입력 표에서도 쓴다
  (`components/Mark.tsx`). 사용자가 한 번만 배우면 된다.
- 회로도 레인과 코드 레인 **사이**의 `crit` 1.5px 가로선이 이음매다.
  한쪽이 비어도 유지한다. 그게 시그니처다.
- `evidence[].highlight` 토큰은 `crit-weak` 배경 + `crit` 굵은 글자.
- 하단은 셋 중 하나 — `unresolved_reason`이 있으면 "판정 보류 사유"(warn),
  `verdict === "PASS"`면 "해제 근거"(ok), 그 외에는 "다음 단계"(무채색).
- 넓은 화면에서는 레인 이름이 왼쪽 열로 빠져 사양표처럼 읽히고,
  375px에서는 이름 아래로 내용이 쌓인다. **두 경우 모두 축의 의미는 그대로다.**

## 5. 디자인 토큰

토스 계열 톤 — **흰 표면 · 넓은 여백 · 부드러운 라운드 · 얇은 회색 선.**
색은 역할 이름으로 부른다.

> **값의 진실은 `tailwind.config.js` 하나다. 이 절은 그 요약이다.**
> 다른 문서(README · 프롬프트 아카이브 · 계약)에 값을 복사하지 않는다.
> 복사본이 5곳에 있었고, 디자인을 한 번 바꾸자 전부 거짓말이 됐다.

```
bg        #F7F8FA   페이지 바탕
surface   #FFFFFF   카드 · 시트
surface-2 #F2F4F6   카드 안에서 한 단 낮은 면 (코드 발췌 · 칩)
ink       #191F28   본문
sub       #4E5968   보조 텍스트
mute      #8B95A1   더 흐린 텍스트 · 비활성
line      #E5E8EB   경계선

brand        #3182F6   강조
brand-strong #1B64DA   버튼 · 링크 (작은 글씨 대비 확보)
crit #D6293E / crit-weak #FEECEE   CRITICAL
warn #B45309 / warn-weak #FFF4E5   WARNING · skipped
ok   #087A57 / ok-weak   #E6F7F1   PASS · cleared · done
```

- 폰트: `Pretendard`(본문) / `JetBrains Mono`(데이터)
- 넷리스트 · 핀 이름 · 코드 · 규칙 ID는 **전부 mono**
- 작은 제목은 대문자·넓은 자간을 쓰지 않는다. **굵기와 색으로 구분한다** (`.label`)
- 라운드: 카드 `20px` · 안쪽 블록 `12px` · 칩 `8px`. 각진 모서리를 쓰지 않는다
- 그림자는 `shadow-card` 하나가 기본. 테두리 + 그림자를 겹쳐 쓰되 둘 다 아주 옅게
- 배지·칩은 **옅은 배경 + 진한 글자**. 테두리를 두르지 않는다
- 버튼은 `.btn-primary`(파랑 채움) / `.btn-ghost`(흰 배경 + 회색 선) 둘뿐
- 헤더는 상단 고정(`sticky`) + 반투명 흰 배경. 좁은 화면에서는 메타 칩을 감춘다

## 6. 범위 밖 — 만들지 말 것

- 로그인 · 회원가입 · 결제 · 가격표
- 마케팅 랜딩 (기능 나열 · 후기 · 가격 · 로고 월).
  `/`는 **한 문장 + 업로드 폼**이다. 제목이 커지는 건 되지만 섹션이 늘어나면 안 된다
- 차트 라이브러리 (요약은 숫자 타일로 충분)
- 상태관리 라이브러리 (fetch + useState로 충분)
- 다크 모드 (8/28까지는 불필요)
- 그라데이션 · 일러스트 · 아이콘 세트 (텍스트와 칩으로 충분하다)
- 애니메이션 — 파이프라인 진행 **하나만**. `prefers-reduced-motion` 존중

## 7. 스택

- Vite + React + TypeScript + Tailwind
- 배포: 나중에 (Vercel 예정). 지금 화면 작업을 막지 않는다
- API 베이스는 `VITE_API_BASE` 환경변수
- 백엔드가 준비되기 전에는 `src/mocks/check.json`으로 개발한다. **기다리지 않는다.**

---

## 8. 접근성 기본선

- 키보드 포커스가 보일 것 (`:focus-visible`)
- **색상만으로 심각도를 구분하지 않는다** — 배지 텍스트를 병행한다
- **마디 모양(■/□)만으로 상태를 구분하지 않는다** — "읽음 / 모름" 글자를 병행한다.
  마디와 레일은 `aria-hidden`이고, 레인은 `aria-label`로 소스 이름을 갖는다
- 375px까지 깨지지 않을 것
- 업로드 슬롯은 드래그앤드롭과 파일 선택 버튼을 **둘 다** 제공

## 9. 코딩 규약

- 사용자에게 보이는 문자열은 한국어
- 컴포넌트 하나에 파일 하나
- API 응답 타입은 `src/types/api.ts`에 계약 그대로 정의하고, 화면에서 임의 변형하지 않는다
- 커밋 메시지는 한국어 한 줄
- 각자 자기 계정으로 커밋한다
