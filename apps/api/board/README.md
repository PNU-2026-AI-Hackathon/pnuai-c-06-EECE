# 우리 보드 — 지금 상태

**여기가 `drift.yml` 이 감시하는 자리다.** PR 마다 이 폴더의 회로도와 코드를 대조하고,
어긋난 것이 그 PR 에서 **새로 생겼으면** 빨간불로 막는다.

    board.net.xml   지금 회로도 (REV2 — 2N3904 레벨시프트 적용본)
    firmware/       지금 펌웨어
    bom.csv         부품 목록

## 왜 `tests/fixtures/` 가 아닌가

역할이 다르다.

| | 무엇 | 바뀌는가 |
|---|---|---|
| `tests/fixtures/` | **그 시점의 기록** | 안 바뀐다. 골든·측정 기준선이 그 위에 서 있다 |
| `board/` | **지금 우리 보드** | 보드가 바뀌면 여기가 바뀐다 |

한동안 `drift.yml` 이 픽스처를 보고 있었다. 그러면 **보드를 고칠 수가 없다** —
픽스처를 건드리는 순간 테스트 20개가 같이 깨져서, 회로도가 바뀐 것인지 규칙이
바뀐 것인지 구분이 안 된다. 워크플로 주석에 *"실제 프로젝트에서는 자기 보드 파일을
여기에 적는다"* 고 적혀 있었는데 그 자리가 없었을 뿐이다.

**이 폴더의 내용을 단정하는 테스트는 두지 않는다.** 보드는 바뀌라고 있는 것이고,
바뀌었을 때 무슨 일이 생기는지는 테스트가 아니라 **드리프트 검사**가 말한다.
